## 1. 文件目的

本文件提供超豐 Agent 工程師整合 HT9045 Handler **遠端 Lot Start** 流程所需資訊：

1. `LotInfo_REQUEST` 內嵌 OEE Start Lot 後的封包格式
2. `LotInfo_REPLY` **異常代碼（Reply Code）對應表** — 客戶可依此快速判斷失敗原因
3. 建議的指令間隔與 timeout 設定（針對「網路速度較慢」場景）

---

## 2. 為什麼要調整流程

V3.33.899.8 之前，超豐 Agent 走以下序列：

```
Agent → LotInfo_REQUEST  → [0] OK
Agent → START_REQUEST    → 機台跳出「Please Start Lot!」modal → 序列卡 12 秒
```

原因：`LotInfo_REQUEST` 只完成「Lot Info 表單層」資料寫入，**未觸發 OEE 系統層的 Start Lot**；後續 `START_REQUEST` 被 OEE 檢查擋下，跳出對話框等人按 OK。

**V3.33.899.x（本方案）之後**：

```
Agent → LotInfo_REQUEST  → [0] OK              (同時完成 Lot Info 寫入 + OEE Start Lot)
Agent → START_REQUEST    → [0] OK (< 1 秒)     (既有，不變)
```

本方案**不新增客戶端可見指令**。客戶仍依照原先提供的順序送 `LotInfo_REQUEST` → `START_REQUEST`，差異只在 Handler 端：當客戶代碼為超豐（`CC_Greatek`）且 OEE 功能開啟時，`LotInfo_REQUEST` 成功後會同步執行原本手動按 Lot Info Start Lot 按鈕才會做的 OEE Start Lot 動作。

## 3. 指令封包格式

### 3.1 Request：`LotInfo_REQUEST`

| Index | 欄位 | 是否必填 | 說明 |
|-------|------|---------|------|
| Data[0] | LotID | **是** | 批號 |
| Data[1] | OperatorID | **是** | 操作員 ID |
| Data[2] | FT-RT | **是** | `0` = FT / 非 `0` = RT（沿用既有 Handler 判斷）|

> `LotInfo_REQUEST` 的參數順序沿用既有規格，不新增欄位，也不要求客戶改變原本送法。

#### 3.1.1 為什麼可以結合在 `LotInfo_REQUEST`

| 規則 | 說明 |
|------|------|
| 1. 資料已齊 | `LotInfo_REQUEST` 收到 LotID / OperatorID / FT-RT 後，OEE Start Lot 所需的 Lot 表單資料已在同一個流程內完成 |
| 2. 客戶端序列不變 | 客戶仍只送 `LotInfo_REQUEST` → `START_REQUEST`，不用新增任何指令 |
| 3. 超豐專用分流 | 只有 `CUSTOMER_CODE==CC_Greatek` 且 OEE 開啟時才會進入內嵌 OEE Start Lot；其他客戶維持舊版行為 |
| 4. 異常不跳窗 | 原本會彈出的 OEE Start Lot alarm 改由 `LotInfo_REPLY` 回傳 Reply Code 與英文 Detail Message |

#### 3.1.2 標準呼叫序列（建議所有正式生產採用）

```
1. LotInfo_REQUEST(LotID, OperatorID, FT-RT)  → [0] OK   ← 已完成 OEE Start Lot
2. START_REQUEST                               → [0] OK
```

#### 3.1.3 何時才需要在 Data 中帶值

`LotInfo_REQUEST` 仍沿用既有三欄位。下表說明是否需要另外增加資料欄位。

| 場景 | 是否帶 Data | 建議做法 |
|------|------------|---------|
| 正常生產 | **帶既有 Data[0..2]** | 標準路徑（建議） |
| 需要設定 MO / Flow / Ticket / Process / Product / TestTimes | **不加在 `LotInfo_REQUEST`** | 仍透過其他既有或專屬指令填寫 |
| 上一批 End Lot 後機台閒置 30 分鐘以上才重新 Start | **重送完整 `LotInfo_REQUEST`** | 長時間間隔可能有人工介入，建議重新初始化 Lot Info |
| 機台剛開機 / 剛進修位後第一批 | **必須先送完整 `LotInfo_REQUEST`** | 機台殘留變數需重新初始化 |

#### 3.1.4 Handler 端處理順序

當 Agent 送出 `LotInfo_REQUEST` 時，Handler 端依下列順序處理：

```cpp
// 偽碼說明
if (CheckCanChangeRealDummy() == false) return 2;

寫入 LotID / OperatorID / FT-RT;

if (CUSTOMER_CODE == CC_Greatek && OEE 功能開啟) {
    執行 silent OEE Start Lot 檢查與 OEE_StartLot();
    if (失敗) return 對應 Reply Code;   // 見 §4
}

return 0;
```

- 超豐以外客戶：`LotInfo_REQUEST` 行為與舊版相同
- 超豐但 OEE 細項未開：`LotInfo_REPLY` 回 Code 3（`OEE function disabled`）
- 超豐且 OEE 開啟：`LotInfo_REPLY` 同時代表 Lot Info 寫入與 OEE Start Lot 結果

#### 3.1.5 為什麼 MO/Flow/Ticket/Process/Product/TestTimes 不在 Data 裡

這些欄位本來就**不是 `LotInfo_REQUEST` 的一部分**。超豐回覆「任何資料未來都是透過其他指令填寫」，意思是：

- MO 由 MO 設定指令或 ini 設定
- Flow / Ticket / Process / Product 同上
- TestTimes / CusStep 同上

因此這些欄位**不新增到** `LotInfo_REQUEST` 參數，永遠以「機台現讀到的值」為準。如需透過 OLP 設這些欄位，請使用對應的專屬指令（與 `LotInfo_REQUEST` 分離）。

#### 範例

標準呼叫（生產建議）：
```
LotInfo_REQUEST,LOT12345,OP9876,0<EOF>
```

RT 模式：
```
LotInfo_REQUEST,LOT12345,OP9876,1<EOF>
```

### 3.2 Reply：`LotInfo_REPLY`

| Index | 欄位 | 說明 |
|-------|------|------|
| Data[0] | Reply Code | 詳見 §4 對應表 |
| Data[1] | Detail Message | 失敗時帶英文原因字串；成功時為空 |

> **語系規則**：Detail Message **一律為英文**，與其他 OLP REPLY（如 `LotInfo_REPLY` / `START_REPLY`）一致。機台不負責中英對照；若客戶端 UI 需中文，請由 Agent 端依 Reply Code 自行查本地化表。

#### 範例

成功：
```
LotInfo_REPLY,0,<EOF>
```

失敗（OP ID 未填）：
```
LotInfo_REPLY,21,Please Enter LotID and Operator ID<EOF>
```

## 4. Reply Code 完整對應表（Alarm Mapping）

> 本表逐一對應原本機台會跳出 modal alarm 的所有觸發點。超豐 `LotInfo_REQUEST` 內嵌 OEE Start Lot 路徑改為回傳 Reply Code，**不再彈出任何對話框**。

### 4.1 成功 / 前置失敗（0~9）

| Code | 觸發條件 | Detail Message | 客戶端建議處理 |
|------|---------|----------------|----------------|
| 0 | Start Lot 成功 |（空） | 繼續送 `START_REQUEST` |
| 1 | 保留 | — | — |
| 2 | 機台 Run 中 / 有殘料 | `Machine running or has residual IC` | 操作員執行 Clean Out + 確認 HALT，再重試 |
| 3 | OEE 系統未啟用 | `OEE function disabled` | 通知 RD/FAE 確認機台 ini 設定 |

### 4.2 必填欄位缺漏（20~29）

| Code | 觸發條件 | Detail Message | 客戶端建議處理 |
|------|---------|----------------|----------------|
| 20 | LotID 空 | `Please Enter LotID` | 重送 `LotInfo_REQUEST` 補 LotID |
| 21 | LotID 或 OperatorID 空 | `Please Enter LotID and Operator ID` | 重送 `LotInfo_REQUEST` 補兩欄 |
| 22 | Cust. LotID 空 | `Please Enter Cust. Lot ID` | 補對應欄位 |
| 23 | Tray ID 空 | `Please Enter Tray ID` | 補 Tray ID（部分客戶模式才需要） |
| 24 | Run Mode 未選 | `Please select run mode` | 重送 `LotInfo_REQUEST` 帶 FT/RT |
| 25 | Line/Process/Product 任一空 | `Please Enter Line and Process and Product Name` | 補對應欄位（CMS Mode 才需要） |
| 26 | OP ID 長度 < 4 | `OP ID Length less than 4` | OP ID 至少 4 字元 |

### 4.3 字元檢查（30~39）

> 凡 LotID / OPID / RunMode / Page / Line / Process / Product 欄位含特殊字元 `\\ / : * ? " < > |` 都會回傳此區段代碼。

| Code | 欄位 | Detail Message |
|------|------|----------------|
| 30 | LotID | `Lot ID contains illegal character` |
| 31 | OperatorID | `OP ID contains illegal character` |
| 32 | RunMode | `Run Mode contains illegal character` |
| 33 | Page | `Page contains illegal character` |
| 34 | Line ID | `Line ID contains illegal character` |
| 35 | Process Name | `Process Name contains illegal character` |
| 36 | Product Name | `Product Name contains illegal character` |

**客戶端建議處理**：上層 UI 過濾掉這些特殊字元後再送 `LotInfo_REQUEST`。

### 4.4 Recipe / 設定檔（40~59）

| Code | 觸發條件 | Detail Message | 客戶端建議處理 |
|------|---------|----------------|----------------|
| 40 | Recipe 自 FTP 下載失敗 | `Recipe download fail` | 確認 FTP server 與網路連線後重試 |
| 41 | 2DID sorting list 找不到 | `2DID sorting list missing` | 上傳 sorting list 到指定路徑後重試 |
| 50 | Setup File name = NULL | `Setup File name is NULL, check TestInfo.txt` | 通知 RD/FAE 檢查 TestInfo.txt |
| 51 | Setup File 不存在 | `Setup File not exist, check TestInfo.txt` | 通知 RD/FAE 確認檔案實際存在 |

### 4.5 環境 / 連線（60~69）

| Code | 觸發條件 | Detail Message | 客戶端建議處理 |
|------|---------|----------------|----------------|
| 60 | Monitor 未連線 | `Please check Monitor connect` | 通知操作員檢查 Monitor 軟體 |

### 4.6 OEE 確認框

> 機台原本會在 Start Lot 前彈出「Are You Sure Start Lot?」確認框。OLP 路徑**自動視為 YES**，不會回傳代碼，也不會阻塞流程。

### 4.7 內部失敗 / 通用（90~99）

| Code | 觸發條件 | Detail Message | 客戶端建議處理 |
|------|---------|----------------|----------------|
| 90 | 其他內部失敗 | 帶實際錯誤字串 | 將 Detail Message 提供給 RD 分析 |
| 91 | Start Lot 完成但仍需手動按 RUN | `Please pressed Start, RUN` | OLP 後續送 `START_REQUEST` 即可 |

## 5. 客戶端建議處理流程（虛擬碼）

```python
reply = send("LotInfo_REQUEST,LOT12345,OP9876,0")
rc = int(reply.Data[0])
msg = reply.Data[1]

if rc == 0:
    send("START_REQUEST")            # 成功，繼續
elif rc in (2, 60):
    notify_operator(msg)             # 機台狀態問題 → 操作員處理後重試
elif 20 <= rc <= 29:
    fix_lotinfo_and_resend(rc, msg)  # 必填缺漏 → 重送 LotInfo_REQUEST
elif 30 <= rc <= 39:
    sanitize_input(rc, msg)          # 字元錯 → UI 過濾後重送
elif rc == 40:
    check_network_and_retry()        # 網路 / FTP → 確認連線後重試
elif rc == 41:
    upload_sorting_list_and_retry()  # Sorting list 缺 → 上傳後重試
elif rc in (50, 51):
    escalate_to_rd_fae(msg)          # 設定檔 → 通知 RD/FAE
else:  # 90, 91 等
    log_and_review(rc, msg)
```

## 6. 通訊建議參數（針對網路速度較慢場景）

> 依超豐 2026-05-04 回饋「客戶端網路速度慢」初估值。實際現場若仍不足請回報具體 RTT 數值，RD 將協助微調。

| 場景 | 建議值 | 說明 |
|------|-------|------|
| `LotInfo_REQUEST` → `START_REQUEST` 間隔 | **≥ 500 ms** | LotInfo 內嵌 OEE Start Lot，且可能含 Recipe / MO / Setup File 下載觸發 |
| TCP keep-alive timeout | **≥ 30 s** | 避免慢網路下被中間設備斷線 |
| `LotInfo_REPLY` 等待 timeout | **≥ 10 s** | Recipe / MO / Setup File 下載最慢場景觀察值約 7 秒 |

## 7. 與既有指令的關係

| 既有指令 | 影響 |
|---------|------|
| `LotInfo_REQUEST` | 超豐 OEE 開啟時會多做 OEE Start Lot；其他客戶完全不變 |
| `START_REQUEST` | **完全不變**，仍須在 `LotInfo_REPLY=0` 後送 |
| 操作員手動按 Lot Info Start Lot 按鈕 | **完全不變**，與 OLP 路徑可並存 |

## 8. 異常排查 SOP

收到非 0 Reply Code 時：

1. **記錄完整 reply 字串**（含 Code 與 Detail Message）
2. 對照本文件 §4 找出對應分類
3. 若分類為 20~39（資料層問題） → 客戶端 Agent 自行處理
4. 若分類為 40~41 或 60（環境問題） → 通知操作員
5. 若分類為 50~51 或 90 → 將完整 reply + 機台時間戳轉給 RD/FAE

RD 端需提供時，請一併附上：
- 該時間點的機台 `Error/` 目錄 log
- `system/Gerneral.ini` 設定
- TestInfo.txt
