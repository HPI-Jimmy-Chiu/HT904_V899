## A. Native 驅動 API 盤點（接縫應接在 wrapper 層）

**核心結論：所有驅動都已封裝在 C++ wrapper 類別（多繼承自 `HTMotor`）。接縫不要接在原始 DLL，而是接在這些 wrapper 上**——可不改既有邏輯、保留錯誤處理與 logging、降低 marshalling 複雜度。

| 驅動 | Wrapper 類別 | 主要檔案 | 實際呼叫 API 數 | Marshalling 難度 | 風險點 |
|------|------------|---------|----------------|-----------------|--------|
| GALIL / DMC | `TMyGALILMotor` | `Motor/myGALILmotor.cpp` | ~7（字串協議 `DMCCommand`） | 低 | `HANDLEDMC` 句柄 → `IntPtr` 生命週期 |
| MN200 / 三菱 | `TMyMN200Motor` | `Motor/myMN200motor.cpp` | ~19（41+ 次呼叫） | **中** | `SPEED_PAR` 結構（多 double，需 `StructLayout(Sequential)` + 對齊檢查） |
| MC88x1 | `CHTML88X1Motor` | `Motor/HTMC88X1Motor.cpp` | ~12 | 低 | 整數暫存器操作 |
| SMC | `TMySMCmotor`(WDM) | `Motor/mySMCmotor.cpp` | 50+（122 次 `SmcW*`） | 低–中 | API 數多，需整理 |
| EtherCAT | `TMyEtherCAT` / `TMyNUEC1` | `EtherCAT/MyEtherCAT.cpp` | ~2 | 低 | PCI 初始化，多為啟動期 |
| KeyPro 授權 | 直接 import | `HS_Function.cpp` / `Public/HTKeyPro.h` | ~5 | **中** | **`std::string` 跨 ABI** → 必須包成 `char* + length` 的 C 函式 |
| CC-Link | `TMyCCLinkCtrl` / `Board` | `CCLink/MyCCLink*.cpp` | ~3 | 低 | 整數參數 |
| SYNTEK / CMNet | `TMySYNTEKmotor` | `Motor/mySYNTEKmotor.cpp` | 低頻 | 低 | — |
| PCI_L1xx | （MN200 基礎） | `Motor/myMN200motor.cpp` | `OpenPCI132` 等 | 低 | 初始化期 |

### 接縫設計建議（C-ABI 分層）
```
C# App → C# P/Invoke Wrapper（新） → extern "C" 導出層（新，薄）
       → 現有 C++ wrapper 類別（TMyGALILMotor / TMyMN200Motor / …） → Native DLL
```

### Critical marshalling 風險清單
| 風險 | 位置 | 對策 |
|------|------|------|
| `SPEED_PAR` 結構封送 | MN200 | `[StructLayout(LayoutKind.Sequential)]` + 手動對齊單元測試 |
| `std::string` 參數 | KeyPro | 接縫改 `char* + length`，不讓 `std::string` 跨界 |
| `HANDLEDMC` 句柄 | GALIL | `IntPtr` + 控制器生命週期管理 |
| 陣列參數 | MN200 多軸移動 | `Marshal.AllocHGlobal` + 明確釋放 |

### 接縫導入優先序
1. 高：MN200（最複雜，先驗證最難的）、GALIL（簡單字串協議，快速見效）、MC88x1
2. 中：SMC、EtherCAT、KeyPro（`std::string` 風險）
3. 低：CC-Link、SYNTEK、PCI_L1xx

## B. 全域狀態盤點與搬移邊界

全域狀態集中在三大結構：
1. **`PROD_INFO_ST Prod`**（cprod.h，~1000+ 成員）— 機械配置/偏移/溫控參數
2. **`iArmTask` / `iInArmTask` / `iOutArmTask` / `iShuttleTask` / `iIndexTask`** — 跨模組編排同步點
3. **即時陣列** `ComATCReceiveOK[]`、`HotTime[2][50][50]`、`iRowOnHotPlate[][][]` — 硬體反饋同步

### 耦合熱點（搬移時最難切的邊界，TOP 5）
| 變數 | 共用模組 | 風險 | 搬移策略 |
|------|---------|------|---------|
| `Prod`（PROD_INFO_ST） | 幾乎全部 | 單一龐大結構 | 保留 native 為主；C# 只讀必要欄位的快取 |
| `iXXXTask` 系列 | Main + 五大手臂 | 跨線程讀寫 | 邏輯/狀態機搬 C#；native 保留低延遲執行器 |
| `HotTime[][][]` | HotPlate + InArm + CatchTray | 2D 矩陣決定吸取時序 | C# HotPlateManager；native callback 更新 |
| `ComATCReceiveOK[]` / `fATCReadBuffer[]` | ATC 線程 + 溫控 + 告警 | 多線程即時通訊 | 保留 native；C# 只讀 query |
| `InArmOffSet[] / OutArmOffSet[]` / `RUN_OFFSET` | 五大手臂 + 教導 + UI | 指標陣列 + 動態加載 | C# 接管編輯/持久化；native 持運行時副本 |

### 即時 vs 編排 初步分界
**保留 native（即時，<100ms 高頻）**：馬達控制/encoder、IO/傳感器/繼電器、ATC 溫控通訊、Shuttle/Index 位置機制、`RUN_OFFSET`/`HotTime` 運行副本。

**搬 C#（編排/非即時/UI）**：`iXXXTask` 狀態機邏輯、批次/Recipe/TRAY_DATA 持久化、計數與良率統計、UI 狀態與告警、偏移教導資料持久化、log/診斷。

**橋接機制**：P/Invoke + Native→C# callback（`ConfigChanged` / `TaskCompleted` / `AlarmOccured`）+ 快取定期同步。
