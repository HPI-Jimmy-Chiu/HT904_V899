1. 系統角色與責任邊界

角色負責內容對外介面
Host / MES批次調度、配方下載、Lot Start／EndSECS/GEM（HSMS over TCP/IP）
AMHS / 派車系統 (HCS / FleetMgmt)接到 Handler 的 AGVSupplement 事件後派遣 AMR 至指定 LoadPortSECS/GEM；對 AMR 走自家協定
AMR（自走車）導航至 Handler、執行 E84 對接、取／放料盤SEMI E84 並行 IO 對接（硬接線）
HT9046LS Handler（本機）產生 SECS 事件、執行 E84 timing、控制 LoadPort 機構、IC 計數SECS（北向）＋ E84（西向）＋ 內部 IO/Cylinder（南向）
關鍵設計：Handler 是「事件發起者」也是「E84 從屬端」。 SECS 層用於 事件通知 + Carrier ID + 計數；E84 層才是真正握手交接料盤的物理協定。 兩條路徑互不依賴但需時序對齊。

2. 完整生命週期時序

2.1 召車（Handler 主動）

  1. 機台執行中發現某 LoadPort（Loader / Empty / Color）感測器顯示無料盤： Sen[SnLoaderTrayHasTray_AGV].IsOff()。
  2. TfLotInfo::CheckLDLevel(iAuto) 將位置編碼成 P1:1,P2:0,P3:0,P4:0,P5:0,P6:0 （P1=Loader, P2=Empty, P3=Color, P4=Auto1, P5=Auto2, P6=Auto3），寫入全域字串 asSupplementBin。
  3. 呼叫 EventReport(SECS_EVENT.AGVSupplement) → 觸發 CEID 272 → SECS S6F11 送出。
  4. Host／HCS 收到後派遣 AMR。

2.2 Host 下達補盤指令（Host 主動，可選）

  1. Host 透過 SECS S2F41 RCMD START_AGV 帶 L 結構參數： 
    L,2
  L,2  <A "Loader">          <A "Action">
  L,2  <A "LoaderTrayCount">  <A "12">
  2. Handler 端 uHGemHT9045.cpp L1655 解析後設旗標：
    • bLoaderSECSActionFlag[0]=true 啟動 Loader 補盤序列
    • iSECSSetTrayCount=12 寫入計數

2.3 AMR 抵達 → E84 對接

  1. AMR 機械對位完成，硬接線拉起 E84 信號 HO_AVBL / CS_0 / VALID，最終 SnE84GO ON。
  2. Handler 端 DoE84Load() 從 Task=1 進入握手狀態機（詳見 §4）。
  3. Handler 依序回應 SwE84LREQ ON → READY ON → ...，AMR 按其節奏放下料盤。

2.4 LoadPort 狀態確認 → SECS 動作回報

  1. 料盤到位：Sen[SnLoaderTrayHasTray_AGV].IsOn()。
  2. LoaderAction() 進入 case 100：發 CEID 273 AGVLDUnLDStatus（動作開始）。
  3. Sensor ON 後進入 case 200：發 CEID 274 AGVLDUnLDFinish（動作完成）。
  4. case 300：刷新 iAMRLDSECSTrayCount、LabDiffTrayCount，並設 bAMRReceiveAGVStart=true。

2.5 退盤（Auto1/2/3）對稱流程

  1. 滿盤偵測：csystem.cpp L6573 起 SearchNeedAMRUnload()，命中後同樣發 AGVLDUnLDStatus / Finish / Supplement 三段式。
  2. 對應 SVID 38234~38236 的 asAMRBinSetting[0..2] 由 AMRUnloadBin() 即時寫入分類 BIN 號。

2.6 結束

  • Lot 結束時 Host 下 END RCMD 或機台主動發 CEID 76 DoLotEnd。
  • 清除旗標： bAMRReceiveLoaderTotalTray=false; bAMRReceiveAGVStart=false; bAMRReceiveStart=false; （uLotInfo.cpp L13265）。

4.4 ES（Emergency Stop）持續輸出邏輯

// 每個 Tick 都先判斷
if (CheckSafeDoor() == false || IsEMGPressed())
    SW[SwE84ES].Off();
else
    SW[SwE84ES].On();
意義：只要安全門打開或機台 EMG 按下，ES 即時 OFF。 E84 規範規定 AMR 偵測到 ES 拉低時必須立即停止任何進入 Port 的動作，這是雙方安全互鎖的最終一道防線。

5. Handler 內部排程器

5.1 主排程：TfLotInfo::CheckAMRAction()（uLotInfo.cpp L13182）

void __fastcall TfLotInfo::Timer4Timer(TObject *Sender)
{
    CheckActionFlag();
    CheckAMRAction();
    ReflashInfo();
}

void TfLotInfo::CheckAMRAction()
{
    for (int i = 0; i < 3; i++)
    {
        LoaderAction(i);     // i=0:Loader, 1:Empty, 2:Color
        UnLoaderAction(i);   // i=0:Auto1,  1:Auto2, 2:Auto3
        if (bLoaderActionFlag[i] == false)
            CheckLDLevel(i); // 主動偵測缺料 → CEID 272
    }
}

7. 互鎖與安全（Safety Interlock）

機械層

  • Middle Cylinder OFF 才允許進入 LoaderAction case 100
  • LoadPort sensor 與 Placement1 必須一致才視為料盤到位
  • 料盤計數差異不為 0 時鎖定退盤動作

電氣層 (E84)

  • SwE84ES 為持續輸出 + Tick-by-Tick 重判
  • READY 信號必須在 LoadPort 物理狀態正確時才 ON
  • Timeout 結束時 LREQ/UREQ/READY 應強制 OFF（建議補強）

SECS 層

  • AMR 模式啟動：TrayForm.bEnableAMR == true
  • REMOTE_START 需 RunInfo.bLotStart == true
  • START 需先進入 LotStart 狀態才會真正啟動 (bAMRReceiveStart)

軟體層

  • Lot 結束統一清旗標：bAMRReceiveLoaderTotalTray / bAMRReceiveAGVStart / bAMRReceiveStart
  • RecordProcess() 軌跡記錄供 hangup 分析

8. 對 IT 與 MES／AMHS 整合的建議

8.1 整合驗收必跑案例

  1. 正常召料：機台主動發 CEID 272 (P1:1) → HCS 派車 → AMR 對接 → CEID 273 → 274 → SVID 38222 +1。
  2. SECS 主動補盤：Host 下 S2F41 START_AGV [["Loader","Action"],["LoaderTrayCount","12"]] → 機台應回 HCACK=0 並進入 LoaderAction → 完成後 SVID 38222 = 12。
  3. 退盤滿盤：連續測試直到 Auto1 滿盤 → CEID 272 (P4:1) → HCS 派空車 → CEID 273/274 → SVID 38225 歸零、38234 紀錄該盤 BIN 名。
  4. E84 完整握手：對接時觀察 LREQ→TR_REQ→READY→BUSY→COMPT→READY off→CS_0/VALID/COMPT 全 off→GO off 全部 12 個轉移點。
  5. EMG 中斷：對接到一半按 EMG → 確認 ES 立即 OFF、AMR 停止、機台 SECS 發 ALARM。
  6. SECS 斷線：kill HSMS → 確認 E84 流程不中斷、重連後狀態同步。

8.2 風險點 / 待確認事項

#議題說明 / 建議
R1E84 timeout 未生效各 case 中 E84LoadDelay.SetSecAndOn(TPx) 只啟動計時，沒有在後續 case 條件中檢查 .Off() 來跳轉 error。建議客戶 IT 在驗收時實機驗證 TP1~TP5 timeout 後機台是否真會發 ALARM；若否須由 RD5 補 timeout error 處理。
R2LoaderAction 300 秒固定case 100 寫死 SetSecAndOn(300)，無法由 SECS／INI 調整。若客戶 AMR 派車時間波動大需可配置。
R3Carrier ID 讀失敗時無 retryRFID.cpp RFID_1ReceiveData 失敗只在 Memo1 顯示，沒有觸發 retry／ALARM。建議 Host 端用 SVID 38202 為空字串作為例外條件。
R4P1~P6 編碼僅 0/1，多目標時順序同時補 Loader+Empty 時 P1:1,P2:1,...；HCS 端必須能解析多 P 同時為 1 並依序派車。
R5SVID 38234~38236 BIN 字串格式由 AMRUnloadBin() 動態產生，建議 IT 提供樣本給 MES 解析測試。
R6MRT vs AMR vs AGV 命名混用本版為歷史合併產物：MR=Mobile Robot 原始命名、AGV=舊代號、AMR=新代號，三者在 SVID/CEID/變數名混用。建議 IT 對照本報告表 §3.2、§3.3 使用，不要依字面分類功能。
R7TrayForm.bEnableAMR 為單一全域開關關閉時所有 AMR 流程降級為手動模式，但 SECS RCMD 解析仍會接受 START_AGV，僅旗標不會被內部排程器處理。建議 IT 驗收時兩種模式都跑。

8.3 推薦監控指標（IT/MES Dashboard）

  • SVID 38222~38227（六位置料盤數）：< 1 時主動觸發排程
  • SVID 38228~38233（六位置 IC 累計）：用於 OEE 與 throughput 計算
  • CEID 272 觸發頻率：過高 = 配料策略需優化
  • CEID 273 → 274 間隔時間：實測 AMR 派車 + 對接時間，作 SLA 基準
  • ALARM CEID（30 DoAlarmReset 等）：與 AMR 對接失敗的相關性分析
