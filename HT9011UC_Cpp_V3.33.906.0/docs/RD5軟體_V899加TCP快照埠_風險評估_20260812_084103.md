# RD5軟體 — V899 生產程式加「TCP 快照埠」風險評估

- 日期：2026-08-12
- 對象版本：`HT9011UC_Code_V3.33.899.0_20260323_Jimmy_20260422`（BCB6，出貨中）
- 目的：讓瀏覽器 HMI 顯示**真實機台資料**，而不必等 V906 的 god-stack 落地
- 狀態：**評估文件，尚未修改任何 V899 程式碼**。等使用者決定後才動。

---

## 1. 提案內容

在 V899 的 `HT9045.exe` 內新增一個**只綁 loopback、唯讀**的 TCP 埠，週期性吐出
機台 tag 快照（行分隔 JSON）。既有的 `wb_gateway.exe` 直接連上它，就能把 Main
網頁餵給 Chrome。

```
HT9045.exe (V899)  --TCP 127.0.0.1:8046-->  wb_gateway.exe  --WebSocket-->  Chrome
   ^ 新增這一段                                ^ 已完成、已測試、不含任何機台程式碼
```

**為什麼值得考慮**：消費端已經做完並驗證過（見 §6），wire 協定已定版且有測試。
V899 側只需要「產生那串 JSON 並送出去」，不需要 HTTP、不需要 WebSocket、不需要
碰網頁。

---

## 2. 風險清單（依嚴重度排序）

### R1 — VCL socket 事件跑在 UI thread，而 SECS 的回覆預算也在 UI thread（高）

V899 所有 `TServerSocket` 都是 `stNonBlocking`（例：`main.dfm:17039`），事件處理函式
是 `TfMain::` 成員（`Command.cpp:12469 / 12692`），**都在 UI thread 執行**。
SECS/GEM 層同樣在 UI thread，且對 host 有 30 秒回覆預算。

> 後果：任何在 socket 事件裡做的重活會直接延遲 SECS 回覆；最壞情況是 host 判定
> T3 timeout，現場看到的是「SECS 突然不回」。

**緩解**：
- 序列化與送出**放在既有的 UI timer**，不要放在 socket 事件裡。
- 每次送出的資料量固定且小（現測 V906 全量快照 922 bytes、閒置心跳 26 bytes）。
- 送出用非阻塞；送不出去就丟棄該筆並記數，**絕不重試到阻塞**。
- 上線前後各量一次 SECS 回覆時間分佈，作為驗收條件（§7）。

### R2 — 不可複製既有的緩衝區溢位寫法（高）

`Command.cpp:12697-12708` 現況：

```cpp
int iBufferLenght = Socket->ReceiveLength();      // 沒有上限
char EthernetBuffer[100];
Socket->ReceiveBuf(EthernetBuffer, iBufferLenght); // >100 bytes 即堆疊溢位
```

這是既有缺陷（**本提案不修它，只是絕不沿用**）。新埠是唯讀的，收到的任何位元組
一律丟棄並計數，單次超過上限就斷線。

> 附帶建議：R2 這個既有溢位本身值得另開一張單處理，因為任何能連上該埠的程式
> 都能弄掉 handler。它與本提案無關，但既然查到了就該記錄。

### R3 — BCB6 不能重用 V906 的 WebBridge 程式碼（中，成本項）

V906 的 `ht9045_webbridge` 用了 `std::chrono`、`enum class`、`= delete`、`std::map`
搭 C++17。**BCB6 一行都編不過**。所以 V899 側必須另寫一份 pre-C++11、用
`AnsiString` 的小實作。

> 這是本提案最大的成本項，也是最容易被低估的地方：wire 協定可以共用，**程式碼
> 不能共用**。

估算：一個新 unit，約 250–350 行（socket 事件 + JSON 字串組裝 + ini 開關）。

### R4 — Big5 → UTF-8（中）

V899 原始碼與字串是 Big5；JSON 必須是 UTF-8。若送出的 tag 值含中文（機種名、
警報字串等）需做 cp950→UTF-8 轉換，否則瀏覽器會看到亂碼。

**緩解**：第一版**只送數值與 ASCII 字串**，明確排除中文欄位；等轉換函式驗過再放行。

### R5 — 動到出貨二進位的一般風險（中）

依既有紀錄，V899 出貨 build 有三個坑：`SOFT_SIMULTE` 常被留著開、版號只有 IDE 會
寫（命令列 build 不跳號，同版號可能編出不同 EXE）、安裝包是加密 7z 無法重現。

**緩解**：新功能整段包在 ini 開關後面，**預設關閉**；關閉時不建立 socket、不註冊
timer 工作，行為與現版完全一致。

### R6 — 埠號衝突（低）

V899 已使用：`1023, 1234, 3000, 5000, 5001, 5002, 5100, 6000, 6666, 7000, 9000,
9001, 10001`，另有 `502`(Modbus)、`6671`(OLP)、`7016/7017`(ART)。
**8046 未被使用**，與 V906 發布端預設值一致。建議 8046，並允許 ini 覆寫。

### R7 — 資安暴露（低，但必須明確）

只綁 `127.0.0.1`，不綁 `0.0.0.0`。這點與 `web/docs/ARCHITECTURE.md` §6 問題 2 的
結論一致：LAN 暴露不可以是預設值。若日後要遠端看，應該在 gateway 那一層處理
（它才是可以獨立改版的那個行程），而不是把 handler 的埠打開。

## 3. 明確不做的事

- 不做命令下行。第一版**唯讀**，沒有任何從網頁控制機台的路徑。
- 不改既有 `TCPCommandServer` / OLP / ART 任何通道的行為。
- 不修 R2 的既有溢位（另案）。
- 不碰 SECS。理由見 §4。

---

## 4. 為什麼不是 SECS（已於程式碼層級否決）

`SECSGEM/uHGemEquipment.cpp:2005-2013` 的 passive 送出路徑：

```cpp
if (ActiveConnections > 0)
  if (Connections[0]->Connected)
    if (ActiveConnections == 1)        // <-- 第二條連線進來就不成立
      Connections[0]->SendBuf(...);
```

web 端若以第二個 SECS host 身分連入，`ActiveConnections` 變 2，**整個送出被靜默
跳過**，handler 對真正的 MES 變啞巴，且沒有 else、沒有 log。`:4037` 又無條件送給
`Connections[0]`。這是生產事故等級，不是效能取捨。

---

## 5. 建議形狀（風險最低的一種）

1. 在 `fMain` 上新增一個 `TServerSocket`，`stNonBlocking`，`Active` 由 ini 旗標決定，
   綁 `127.0.0.1:8046`。沿用專案內既有 12 個 TServerSocket 的相同模式。
2. **在既有 UI timer** 內組出 JSON 字串並送出，socket 事件只做 accept / 斷線清理。
3. 輸出格式與 V906 發布端**逐位元組相同**（`WebBridge/TcpTagLink.h` 已定版），
   如此 `wb_gateway.exe` 不必改一行就能同時支援 V899 與 V906。
4. 收到的位元組一律丟棄並計數，單次超過 4 KB 就斷線。
5. 送出佇列有上限，超過就丟棄該客戶端，**絕不讓它拖慢 UI thread**。

## 6. 消費端現況（已完成，可直接沿用）

| 元件 | 狀態 |
|---|---|
| `wb_gateway.exe` | 已編出，只 link `ht9045_webbridge`，**不含任何機台程式碼** |
| wire 協定 | 已定版：行分隔 JSON，`hello` / `snapshot` / `patch` / `ping` |
| 自動測試 | `test_wb_tcplink`（ctest `WB_TcpLink`），53 checks 全過，含斷線重連 |
| 端到端 | `wb_publish → TCP → wb_gateway → WebSocket → Chrome` 已實跑通過 |

也就是說：**V899 這一側是這條鏈上唯一還沒做的環節。**

## 7. 驗收條件（若決定執行）

1. ini 旗標關閉時，與現行版本行為逐項一致（socket 不建立、timer 無額外工作）。
2. 開啟後連續 8 小時，`dropped=0`、無記憶體成長。
3. **SECS 回覆時間分佈，開啟前後比對**，作為 R1 的量化證據。
4. 惡意輸入測試：大量位元組、半行、亂碼、突然斷線，handler 不得崩潰或卡住。
5. 拔掉 gateway、重啟 gateway，handler 不受影響。
6. 完整回歸：至少涵蓋 SECS 上線/下線、Lot Start/End、警報回報。

---

## 8. 需要使用者決定的事

1. **要不要動出貨程式**。不動的話，Main 網頁只能顯示 V906 目前載得到的資料
   （43 個 tag，其中 8 個有值，其餘為 `---`）。
2. 若要動，**是否接受第一版只送數值與 ASCII**（規避 R4 的中文轉碼）。
3. 要掛在哪一個 V899 分支／出貨版本上。
